# mtc-link

作者：苏勃(subo)

许可：Apache-2.0，全文见仓库根目录 `LICENSE`。版权苏勃。

电摩充电机与电池管理系统（BMS）的通信基础。`mtc-solo`、`mtc-dock`、`mtc-meter`、`mtc-pile-sim` 和 `mtc-crypt` 都依赖本仓。本仓不依赖它们。

本仓已按个人项目公开，当前版本 0.1.1。公开文本不出现公司、客户、供应商、价格、具体料号和具体机型。

## 用途

规定一次充电会话里 BMS 与充电机交换的报文、三种物理口的装法、可选的通信加密，以及双方都必须执行的电气匹配。充电机按充电控制决定请求。没有合法充电控制时，输出电流为 0，不得改成盲充。新鲜有效的电池信息按 `doc/protocol.md` 第 5.7 节可使本周期输出为 0，不改请求电流。

一台充电机在隔离 RS-485、CAN、一线通里只使用一个口。一次会话不换口。

## 本仓包含

- 四条报文。`0x01` 是充电控制，携带允许、暂停、停止、恒压、请求电压和请求电流。`0x02` 是充电机能力和就绪。`0x03` 是充电机实测电压、电流和故障。`0x04` 是电池信息。`0x04` 不把输出电流往上加，充电机不应答。
- 帧壳。一线通和 RS-485 以 `A5 5A` 开头，版本 `0x01`，CRC-16/MODBUS，低字节在前。多字节字段小端。`0x01` 到 `0x04` 已有字节保持不动，保留位非 0 的帧整帧丢掉。认证和加密使用 `0x05` 起的新报文。
- 三个口。RS-485 为隔离半双工、9600 8N1，无站地址；BMS 每 250 ms 发送 `0x01`，充电机在约 80 ms 内应答。CAN 为 250 kbit/s、8 字节帧，BMS 源地址 `0xF4`，充电机源地址 `0x56`，装的仍是 `0x01` 的请求电压和请求电流；停机认 BST，只收到电流为 0 的 BCL 时输出为 0、会话保留。一线通由 BMS 发送，充电机发送脚不接线，充电机不回传。
- 明文套件 `0x00`。只做 CRC-16，必须实现。
- 公开可选套件 `0x01`。动态令牌加盐：双方各出 8 字节盐。标签密钥由长期密钥、两只盐和两只编号派生，再对覆盖内容做 HMAC-SHA256，取前 8 字节。覆盖内容是两只盐、计数、方向，以及本拍 `0x01` 和最近一帧 `0x04`。
- 厂商扩展槽。套件号 `0x80`–`0xEF` 只规定外壳：套件号、长度、不透明正文，仍放在标准帧壳和 CRC 里。算法放在 `mtc-crypt`，经解包钩子交回标准的 `0x01` 和 `0x04`。解包失败则输出为 0。
- 一对一绑定和封条。出厂在本地写入同一把 16 字节密钥，BMS 写入这只充电机的编号，充电机写入这只电池的编号。编号不一致、封条断开，或在一线通上做了绑定，输出保持 0。重新匹配和清除封条只做这次本地写入。步骤在 `doc/protocol.md` 的 5.6.1。
- 电气匹配。有一帧新鲜且有效的电池信息时，充电机最大电压高于电池最高允许充电电压，或两侧化学体系都已声明且不相同，本周期输出为 0，会话保持。允许电流不改请求电流。电池信息无效、超过 3 秒，或化学体系有一侧未声明时，家充回到只按充电控制。锁压就是本机最大输出电压，不另设一只不同的上限。请求不高于锁压时按请求执行，不得抬回锁压。高出不超过 0.5 V 时电压目标停在锁压。再高的帧无效，不改锁压。请求电流高于锁流时停在锁流。规范不写锁压的具体伏特数。

## 本仓不包含

- 不对接充电桩时的 1 秒超时判定。那是 `mtc-solo`。
- 对接充电桩时电池字段能否交出。那是 `mtc-dock`。
- 充放电倍率表。那是 `mtc-strategy`。本仓的输入只有允许、请求电压和请求电流。
- 仪表脉宽帧。那是 `mtc-meter`。
- 桩的报文、枪、导引和硬件。桩侧模拟器是 `mtc-pile-sim`。
- 厂商私有算法的轮数、密钥表和实现。那是 `mtc-crypt`。
- 具体机型、接插件、外壳和价格。

## 加密怎么选

步骤、报文和封条写在 `doc/protocol.md` 的 5.6.1。这里只留选择结果。调用顺序在 `chg_crypt/README.md`。电压和电流仍按 5.7，绑定不放宽上限。

| 配置 | 口 | 结果 |
|------|----|------|
| 不启用 `chg_crypt` | 三个口 | 现有明文会话 |
| 套件 `0x01`，未绑定，未要求双向盐 | RS-485、CAN 或一线通 | BMS 令牌通过后按 5.7 出流。一线通的充电机盐为 0 |
| 套件 `0x01`，未绑定，要求双向盐 | RS-485 或 CAN | 两个方向的令牌都通过后按 5.7 出流。充电机令牌超过 1 秒未再通过，允许位回到 0 |
| 已一对一绑定 | RS-485 或 CAN | 密钥相同、编号与出厂写入一致、充电机令牌已通过且未超过 1 秒、每一拍 BMS 令牌通过、封条闭合，才出流 |
| 已绑定，或要求双向盐 | 一线通 | 输出保持 0。充电机发不回帧 |
| 封条断开，或对端 hello 的封条位为 1 | 三个口 | 输出保持 0。充电帧不能清除 |
| 没有共同的可执行套件 | 三个口 | 双方都允许明文则用明文。已绑定的明文仍不出流。有一方不允许明文时，就绪保持 0，输出保持 0 |
| 0 档 BMS，1 档充电机，未绑定 | 三个口 | 协商成明文并出流。0 档只列 `0x00` |
| 0 档或协商成明文，已绑定 | 三个口 | 输出保持 0 |
| 去掉 HMAC 的映像，或尚未安装 HMAC | 三个口 | 不能执行 `0x01`。1 档 hello 也只列 `0x00`。双方都允许明文则用明文 |

0 档给放不下令牌的 BMS。1 档给剩余程序和 RAM 够用的 BMS，也给充电机。32 位的门槛是程序 8 KB、RAM 2 KB。8051 的门槛是程序 24 KB、外部 RAM 1 KB。两块令牌状态不超过 1 KB。`chg_crypt_level_suites` 按档填写 hello。

双方都能执行的套件里，取编号最大的一个。`0x00` 不参加这组比较。`0x80`–`0xEF` 要双方都列出，并且本机钩子已接上。

重新匹配只在工装或检修口调用 `chg_crypt_factory_activate`。两台都写同一把密钥，并写成对方的编号。只写一台时，另一台仍认旧编号。

## 出流剖面

三个仓的当前版本是 0.1.1。出流超时分成两个剖面，不混用。

- 链路剖面以本仓为准。不满 1 秒不停，到 1.2 秒输出为 0。参考实现和主机测试都按这一条。
- 家充剖面以 `mtc-solo` 为准。满 1 秒没有合法 `0x01`，输出已经是 0。
- 对接充电桩时，BMS 口仍用链路剖面。朝向桩的交接另按 `mtc-dock`。桩侧超时不改 BMS 口。

一台机器只符合家充剖面或对接剖面其中一份。

## 现状

报文实现在 `chg_bms`、`chg_charger`、`chg_link` 和 `e2e`。令牌在 `chg_crypt`。报文正文在 `doc/protocol.md`。

`0x01`–`0x04` 的会话仍只做 CRC-16。明文模块不链接令牌。启用时先 `chg_crypt_install_hmac`，会话壳经函数指针调用哈希，不按符号链接它。`chg_crypt_observe` 只读已经组好的 `0x01` 和 `0x04`。`chg_crypt_cover_ctrl` 在允许位不能置 1 时清掉 bit0，套件 `0x01` 时另组 `0x07`。认证帧不改明文报文。校验失败、绑定未通过或封条断开时，输出保持 0。厂商算法不在本仓。实板尚未测量。

```bash
make -C chg_bms test
make -C chg_charger test
make -C chg_crypt test
make -C e2e test
```
