## 2. 电气架构

功率路径和通信路径，见图 4。


功率和通信分成两层。

**功率层。** 充电机直流输出接到电池包充电口，经 BMS 充电 MOS 进电芯。通信线不串在这条功率路径上。交直流一体机的交流路径和直流路径不得同时闭合；两路同时有效时输出保持 0 A。

**通信层。** 同一次充电只接一个口。订单在一线通、CAN、RS-485 中三选一，并写明用哪一个。订单没写协议时不默认改口：按充电机产品线，未选协议的机器按锁压、锁流充电，不装这三口。料号只引出一个口时，充电机做这一个口。

**地。** 通信地在电池包地一侧，和包地同一参考。通信地不接到桩侧高压地。

**隔离。** 充电机内部把桩侧和包侧分开。桩侧的 S+/S−、CC2、枪温、CP 止于桩侧腔，不进 BMS。充电 CAN、充电 RS-485 相对桩侧隔离。一线通在包地一侧，开漏，不跨到桩地。

| 口 | 信号 | 电气 |
|----|------|------|
| 一线通 | SIF、GND | 开漏，9600。BMS 发送，充电机只收。上拉 **5 V / 2.2 千欧**。充电机发送脚不接 SIF。一线通协议的仪表可以并在同一根 SIF 上，只听 |
| CAN | CANH、CANL、GND | 250 kbit/s，CAN 2.0B，29 位标识符。独立充电 CAN，与桩 CAN 不共线。终端电阻 **120 欧**，由哪一端焊接须书面确认 |
| RS-485 | 485A、485B、GND | 隔离差分，默认 **9600 8N1**。工具 485 另用插座，充电过程中只读 |

辅助电源标明 12 V 或 24 V 及欠压点，不灌入 BMS 采样。功率线径按持续电流选取。

## 3. 上下电与交互流程

这一节按时间走完一次充电。下表先给出每一步的目的和报文。图和后面的分表是同一条线的展开。异常的判据在第 4 节。字段定义在第 5 节。

下表是端到端交互的主干。每一行同时给出这一步的目的和报文内容。三个口的字节差异写在报文列里。主机模拟按这九步核对，命令在第 9 节。

| 步 | 目的 | 报文内容 | 输出 |
|----|------|----------|------|
| 1 上电 | 两侧初始化，确认还没有能量 | 无报文。直流输出断开，充电 MOS 断开 | 0 A |
| 2 握手 | 确认链路，并让充电机申报能力。这一步不出流 | BMS 发 `0x01`，允许 = 0，电流 = 0，帧尾 `7C 5D`。RS-485 应答 `0x02`，就绪 = 0，帧尾 `E7 EC`。CAN：BRO = 00，BCL 电流字段为 0，CML，CRO = 00 | 0 A |
| 3 电池信息 | 在出流之前把电池数据交给充电机，供桩侧填写。不改变电流，不计入握手 | `0x04`，样例帧尾 `C0 92`。CAN 为四帧 `18EF56F4`。一线通和 CAN 可与第 2 步处于同一发送周期发出。RS-485 在第一次应答之后的下一发送周期发出，充电机不应答 | 0 A |
| 4 就绪 | 充电机表示可以接受非零请求。真实请求到达前仍不出流 | 一线通：合法 `0x01` 满 3 帧。RS-485：再发握手，应答 `0x02` 就绪 = 1，帧尾 `EA 7C`。CAN：CRO = AA 之后，BRO 改为 AA | 0 A |
| 5 能量传输 | 按 BMS 的请求闭合功率级 | `0x01` 允许 = 1，84.0 V / 40.0 A，帧尾 `7C 31`。RS-485 应答 `0x03`，83.6 V / 39.8 A，帧尾 `8C A7`。CAN：BCL `48 03 30 11 02`，CCS `44 03 2E 11 00 01 01 00` | 40.0 A |
| 6 暂停 | 本会话内把电流降到 0，会话保持。桩侧暂停满 10 min 则发 CST 结束 | 标志字节 `0x03`，帧尾 `7D D3`。CAN：BSM 字节 6 为 `0x00`。请求电压、请求电流保持原值 | 0 A |
| 7 恢复 | 继续按请求出流，不重新握手 | 与第 5 步同一帧 `7C 31`。若该发送周期轮到 `0x04`，先发电池信息，下一发送周期再发本帧。CAN：BSM 字节 6 回到 `0x10`。收到恢复帧只置位，`chr_link_tick` 的第一拍电流不超过 20.0 A、电压目标为请求电压减 1.0 V。这一拍若充电机故障，输出为 0 A，置位保留到故障消失后的第一拍 | 第一拍 ≤20.0 A，下一拍 40.0 A |
| 8 停止 | 结束本次会话。下一次非零电流必须重新握手 | 一线通、RS-485：能量传输中停止 = 1，或请求电流 = 0，帧尾 `7D D9`。握手期间电流 0 不结束会话。CAN：发 BST `01 00 00 00` 才结束；只收到 BCL 电流为 0、没有 BST 时输出 0 A，会话保持。停留在停止期间 BST 按 10 ms 重发。充电机断开直流输出。BMS 在 1 秒内断开充电 MOS | 0 A |
| 9 下电 | 链路上不再出现新帧 | 应用停止调用，或辅助电源撤掉。再次上电从第 1 步开始，就绪位不保留 | 0 A |

|------|------|------|----------|------|

| RUN | HS 满足条件 | 一线通、RS-485：停止位 = 1，或能量传输中请求电流变为 0，或 T_loss。CAN：收到 BST，或 T_loss。只把 BCL 电流写成 0、没有 BST：留在 RUN，输出 0 A | 由 `0x01` 与上限决定 | T_loss 标称 1000 ms、最迟 1200 ms。BMS 看 CCS 或能量传输中的 0x03；充电机看 BCL 或 0x01。0x04、BRO、BSM、CML、CRO、0x02 不刷新。非 SIF 超时后同一拍回到 HS；一线通留到下一次非零请求再握手 |

| 口 | 第一次发送 | 之后 | 本周期输出电流 |
|----|------------|------|------------------|
| 一线通 | 第一次调用 `bms_link_tick` 即发送，与第一帧握手 `0x01` 处于同一发送周期。不计入连续 3 帧 | 约每 1 s。到点时与当前周期 `0x01` 一起发出，不替换 `0x01` | 不因本帧改变 |
| RS-485 | 第一帧 `0x01` 被合法应答收下之后的下一发送周期。此时仍是握手，请求电流为 0。充电机不应答 | 约每 1 s 单独占用一个发送周期。该发送周期两侧的两次 `0x01` 间隔约 500 ms，其余 `0x01` 仍为 250 ms | 不改电流，不刷新 T_loss |

### 3.2 从上电到下电

一次充电从两侧完成初始化开始，到能量撤掉、两侧不再出流结束。下面先给整体设计：每一行同时是控制报文和强电。然后按一线通、RS-485、CAN 各给一张。接触器 1 s 内断开是功率时限，与 T_loss 不是同一只计时器。






| 状态 | 通信 | 电池信息 | 功率 |
|------|------|----------|------|
| 1 上电 | `bms_link_init`、`chr_link_init` 之后为 OFF。第一次调用 tick 之前没有合法 `0x01`。充电机第一次 tick 进入握手：CAN 发送就绪 = 0 的 CML/CRO；一线通与 RS-485 等待 `0x01` | 不发送 | 输出 0 A。直流输出断开，BMS 充电 MOS 断开。一线通上拉关闭 |
| 2 握手 | 请求电流大于 0 时，第一个发送周期发送允许 = 0、电流 = 0 的 `0x01`，OFF→HS。请求电流为 0 或停止位则直接 STOP，不出流 | 按第 3 节的第一次发送 | 0 A |
| 3 就绪 | 一线通数满 3 帧合法 `0x01`。CAN 见到 CRO = AA。RS-485 见到就绪 = 1 的 `0x02`。BMS 随后才发送允许 = 1 的真实请求 | 不代替该口的就绪条件。有效位为 0 也不挡住本状态 | 真实请求到达充电机之前仍为 0 A |
| 4 能量传输 | 允许 = 1，暂停 = 0，停止 = 0，请求电压 > 0，请求电流 > 0，且链路与能力条件满足。恒压位表示电压目标取请求电压，电流仍不超过请求电流 | 按第 3 节的周期继续 | 输出电流 = min(请求电流, 最大输出电流) |
| 5 暂停 | 标志字节为 `0x03`，或 CAN 的 BSM 字节 6 为 `0x00`（flags 为 0；未暂停为 `0x10`）。会话留在 RUN | 周期不中断。RS-485 若恢复所在周期轮到 `0x04`，先发电池信息，下一发送周期再发恢复请求 | 0 A。暂停清除后从 0 A 恢复，不重新握手 |
| 6 停止 | 停止位，或能量传输中一线通、RS-485 的请求电流变为 0，或到 1.2 s 仍无合法输出目标帧。CAN 上结束会话发 BST。下一次非零电流必须重新握手。停止后只收到能量传输帧时，输出保持 0 A | 一线通、CAN 继续按周期发送。RS-485 不再发送 | 0 A。充电机断开直流输出。BMS 在 1 s 内断开充电 MOS。这 1 s 与 T_loss 分开计 |
| 7 下电 | 应用不再调用发送，或辅助电源撤掉。链路上不再出现新帧 | 随发送停止而停止 | 接触器与充电 MOS 保持断开。再次上电从状态 1 开始，就绪位不保留 |

## 4. 异常处理

这一节是异常的唯一判据。先按结果分成四类，见图 14。表里是每一条的处理。帧壳丢弃的字节规则见第 5 节。


| 现象 | 处理 | 输出电流 | 会话 |
|------|------|----------|------|
| 帧头不是 `A5 5A`，VER 不是 `0x01`，CRC 错误，LEN 越界，或报文号不在 `0x01`–`0x08` | 整帧丢弃，不刷新 T_loss | 不变 | 不推进 |
| 报文号为 `0x05`–`0x08`，充电状态机未启用令牌模块 | 状态机整帧丢弃，不刷新 T_loss，也不把它们当作 `0x01` | 不变 | 明文会话照常 |
| 令牌标签错误、计数不连续或方向不符，连续满 3 次 | 结束会话。10 s 内不再接受新的握手，盐作废 | 0 A | 10 s 后从 `0x05` 重新开始，并更换盐 |
| 要求双向盐，口却是一线通 | 握手组不出来 | 0 A | 保持未出流 |
| 已做一对一绑定，对端编号与出厂写入不一致，或口是一线通 | 令牌不能单独放行 | 0 A | 保持未出流。重新配对只做本地写入 |
| 本机封条已断开，或对端握手的封条位为 1 | 锁存。充电帧不能清除 | 0 A | 保持未出流，直到本地重新写入 |
| 有一方不允许明文，且没有共同的可执行套件 | 就绪保持 0 | 0 A | 保持未出流 |
| 厂商解包钩子返回失败 | 与标签失败相同 | 0 A | 保持未出流，不改走明文 |
| `0x01` 保留位非 0，BCL 模式不是 `0x01`/`0x02`，或 BRO、CRO 不是 `0x00`/`0xAA` | 整帧丢弃，不刷新 T_loss | 不变 | 不改变允许位、就绪位和已保存的请求 |
| 字节间隔大于 50 ms | 丢掉半帧，重新寻找帧头 | 不变 | 半帧不算应答 |
| RS-485 应答晚于 80 ms，或不在等待应答时到达 | 丢弃。BMS 下一发送周期重发 `0x01` | 不变 | 不刷新 T_loss |
| RS-485 能量传输中到 1.2 s 没有合法应答。不满 1 s 不停 | BMS 发送停止帧 | 0 A | BMS 进入 STOP |

## 5. 报文定义

本章每条报文都对照第 1 节的整体结构：0x01 是充电控制，0x02 是充电机能力，0x03 是充电机状态，0x04 是电池信息。一线通与 RS-485 把它们放进帧壳；CAN 不使用帧壳，按第 1 节的 CAN 实现结构拆帧。然后再给字节图、起始字节表和示例。发送时刻见第 3 节。输出电流判定见 5.7。多字节字段为小端。物理量 = 分辨率 × 原始值 + 偏移量。一线通与 RS-485 的电压、电流偏移量为 0。CAN 电流字段偏移量为 −400 A，见第 8 节。电压、电流分辨率 0.1，除非另有说明。

### 5.1 帧壳

一线通与 RS-485 采用下列帧壳，见图 15。CAN 的标识符见第 8 节，不采用本帧壳。


```
A5 5A | VER | MSG | LEN | DATA | CRC_L | CRC_H
```

| 字段 | 长度 | 取值 |
|------|------|------|
| 帧头 | 2 字节 | `A5 5A` |
| VER | 1 字节 | `01` |
| MSG | 1 字节 | `01` 充电控制，`02` 能力，`03` 状态，`04` 电池信息。`05`–`08` 为认证，见 5.6.1。其他报文号不发送 |
| LEN | 1 字节 | DATA 字节数 |
| DATA | LEN 字节 | 见 5.3 至 5.6 |
| CRC | 2 字节 | Modbus CRC-16，多项式 0xA001，初值 `0xFFFF`，自帧头至 DATA 末字节，不含 CRC 自身，低字节在前。帧内没有站地址 |

VER 或 CRC 不对的帧应丢弃，且不得刷新 T_loss（通信超时，1 s）计时。

### 5.3 充电控制（BMS → 充电机）

报文功能：BMS 向充电机给出允许、暂停、停止、恒压以及请求电压、请求电流。充电机只根据本报文出流。报文号 `0x01`。字节、位和示例如图 16。


| 起始字节 | 位 | 长度 | 分辨率 | 含义 |
|----------|----|------|--------|------|
| 0 | 0 | 1 bit | — | 允许。1 = 允许进入能量传输 |
| 0 | 1 | 1 bit | — | 暂停。1 = 本会话内输出 0 A，链路保持 |
| 0 | 2 | 1 bit | — | 停止。1 = 结束会话，输出 0 A |
| 0 | 3 | 1 bit | — | 恒压。1 = 按请求电压做恒压；0 = 恒流 |
| 0 | 4–7 | 4 bit | — | 保留，填 0 |
| 1 | — | 2 字节 | 0.1 V | 请求电压，小端 |
| 3 | — | 2 字节 | 0.1 A | 请求电流，小端。为 0 时输出 0 A。是否结束会话见第 3 节步骤 8 |
| 5 | — | 1 字节 | — | 保留，填 0 |

暂停时标志字节为 `0x03`，请求电压与请求电流保持不变。停止时标志字节为 `0x04`，请求电流为 0。字节 0 的 bit4–bit7 和字节 5 必须为 0。任一不为 0 时，充电机丢掉整帧，不刷新 T_loss，不计入握手，也不应答。

```
A5 5A 01 01 06 01 48 03 90 01 00 7C 31
A5 5A 01 01 06 03 48 03 90 01 00 7D D3
A5 5A 01 01 06 04 48 03 00 00 00 7D D9
```

上列三帧依次为能量传输 84.0 V / 40.0 A、暂停、停止。`48 03` 为小端 `0x0348` = 840，即 84.0 V；`90 01` 为小端 `0x0190` = 400，即 40.0 A。帧壳不加 4000。同一 40.0 A 在 BCL 里才是 `30 11`。

### 5.4 充电机能力（充电机 → BMS）

报文功能：充电机向 BMS 申报输出范围和就绪。握手时发送，能力变化时再发。一线通不以本报文传输，改以书面参数给出。报文号 `0x02`。字节和示例如图 17。最小输出电流只用于申报能力。


| 起始字节 | 位 | 长度 | 分辨率 | 含义 |
|----------|----|------|--------|------|
| 0 | 0 | 1 bit | — | 就绪。1 = 可以接受非零请求 |
| 0 | 1–7 | 7 bit | — | 保留，填 0 |
| 1 | — | 2 字节 | 0.1 V | 最小输出电压 |
| 3 | — | 2 字节 | 0.1 V | 最大输出电压 |
| 5 | — | 2 字节 | 0.1 A | 最小输出电流。仅申报，不得用于填补零请求 |

就绪 = 1、50.0–100.0 V、1.0–80.0 A：

```

```

`F4 01` 是最小电压 50.0 V，在最大电压前面。电流不加 4000：1.0 A 是 `0A 00`，80.0 A 是 `20 03`。CAN 的 CML 相反：最大电压在前，电流加 4000。不要把这帧的 `F4 01` 放到 CML 的字节 0。

### 5.6.1 认证与令牌

`0x01` 到 `0x04` 的字段保持不变。认证使用 `0x05` 到 `0x08`，帧壳和 CRC 仍按 5.1。充电状态机不解析这些报文，不刷新 T_loss，也不把它们当作充电控制。调用方不启用令牌模块时，状态机整帧丢弃，出流规则与明文会话相同。

明文套件 `0x00` 必须实现。双方都不启用令牌模块时，会话就是现有的明文会话。

公开套件 `0x01` 使用 16 字节长期密钥。密钥只在出厂或检修时写入，不出现在帧里。一次会话里 BMS 与充电机各出 8 字节盐。令牌是 HMAC-SHA256 的前 8 字节，覆盖套件号、两只盐、本方向计数、方向、本拍 `0x01` 的 6 字节，以及最近一帧 `0x04` 的 28 字节。每个方向的计数从 1 起，逐次加 1。重放、跳号或标签不对记一次失败。

一线通上充电机发不回帧。这一口只由充电机核对 BMS 的令牌，充电机盐为全 0。要求双向盐的会话在一线通上完不成，输出保持 0。双向盐使用 RS-485 或 CAN。

RS-485 上 BMS 先发 `0x05`。充电机在 80 ms 内只回 `0x06`，`0x02` 延后。此后每一拍 `0x01` 带一帧 `0x07`。连续 3 次标签失败后结束会话，10 s 内不再握手。恢复后更换盐。

CAN 标识符为 `0x181656F4`（BMS → 充电机）和 `0x1816F456`（充电机 → BMS）。数据第 1 字节是序号，从 0 起，其后最多 7 字节。拼回的第 1 字节是报文号，第 2 字节是 DATA 长度。

厂商套件 `0x80`–`0xEF` 走 `0x08`：套件号、长度、不透明正文。解包钩子交回标准的 `0x01`（6 字节）或 `0x04`（28 字节）。钩子失败则输出为 0。算法不在本规范里。

标志字节的 bit0 为 1 表示允许在没有共同套件时使用明文。bit1 为 1 表示要求双向盐。bit2 为 1 表示发送方封条已断开。其余位必须为 0，否则整帧丢掉。bit2 只用于报告。收到 bit2 为 1 的握手后，本端输出保持 0。任何 `0x05`–`0x08` 都不能把封条清掉。

双方都列出的可执行套件里，取编号最大的一套。`0x00` 不参与这组比较。没有这样的套件时：双方都允许明文则用明文；有一方不允许则就绪保持 0，输出保持 0。

身份名单只在套件核对通过后生效。名单为空且打开身份限制时，输出保持 0。明文会话里的编号不作为身份证明。打开身份限制时，明文会话的输出保持 0。

一对一绑定比身份名单更严。出厂或检修时，在本地写入同一把 16 字节长期密钥，并在 BMS 写入这只充电机的编号、在充电机写入这只电池的编号。充电帧里不写密钥，也没有重新配对的报文。对端编号与这只写入不一致时，令牌即使算对，输出仍保持 0。换成另一只电池或另一只充电机，密钥或编号对不上，会话不能出流。重新匹配要在两台设备上各做一次本地写入，写入后旧的对端失效。

这种绑定要求互相认证，口使用 RS-485 或 CAN。一线通上充电机发不回帧，BMS 核对不了充电机，绑定保持关闭，输出保持 0。

封条断开后锁存。BMS 监测电池包是否被打开，可以用压力或等效的开盖检测：判据是开盖造成的变化并锁存，不用一个固定的绝对气压门限，以免海拔或温度造成误触发。充电机监测自身壳体被打开，锁存方式相同。锁存要放在掉电仍保留的存储里。上电读到已断开，就保持不能出流。清除锁存只和重新配对走同一次本地写入。充电口上的报文清不掉。

封条锁存期间，BMS 的允许位保持 0，充电机输出保持 0。打开壳体后仍使用原来的 BMS 或充电机时，这一锁存使它不能继续出流。更换整块控制板同时要有原长期密钥才能通过令牌；密钥读不出来时，换板也出不了流。

`0x05` 的 DATA 共 22 字节。

| 起始 | 长度 | 含义 |
|------|------|------|
| 0 | 1 | 标志 |
| 1 | 1 | 套件数，1 到 4 |
| 2 | 4 | 套件号，不足的字节填 0 |
| 6 | 8 | BMS 盐 |
| 14 | 8 | BMS 编号 |

`0x06` 的 DATA 共 18 字节。选定套件为 `0xFF` 时表示拒绝，盐填 0。

| 起始 | 长度 | 含义 |
|------|------|------|
| 0 | 1 | 标志 |
| 1 | 1 | 选定套件 |
| 2 | 8 | 充电机盐 |
| 10 | 8 | 充电机编号 |

`0x07` 的 DATA 共 13 字节。方向 0 为 BMS，1 为充电机。计数为小端。

| 起始 | 长度 | 含义 |
|------|------|------|
| 0 | 1 | 方向 |
| 1 | 4 | 计数 |
| 5 | 8 | 标签 |

HMAC 的输入按下面的顺序拼成 57 字节：套件号 1、BMS 盐 8、充电机盐 8、计数 4（小端）、方向 1、`0x01` 载荷 6、是否已有 `0x04`（0 或 1）、`0x04` 载荷 28。还没有 `0x04` 时，最后 28 字节为 0。

`0x08` 的 DATA 为套件号 1 字节、正文长度 1 字节、正文。正文最长 24 字节。

参考实现放在 `chg_crypt`。工作区由调用方提供，模块内部不分配内存。本机测量见该目录的 README。实板尚未测量。

### 5.7 输出电流判定

输出电流只由 `0x01` 与能力、链路、故障条件共同决定，见图 20（apply 决策树）。`0x04` 不参与本判定。电压目标取请求电压，且不得超过最大输出电压。最大输出电压或最大输出电流为 0 时，输出为 0 A。任一条件不满足时，该发送周期的输出为 0 A。逐条异常仍以第 4 节的表为准。

启用套件 `0x01` 或厂商套件后，本拍令牌或解包未通过时，输出电流再被置为 0。未启用令牌模块时，本判定与明文会话相同。

### 5.9 组帧接口

完整帧已随 5.3 至 5.6 给出。组帧函数按工程分开。BMS 工程提供 `chg_ctrl_pack` 与 `chg_bat_pack`。充电机工程提供 `chg_cap_pack`、`chg_stat_pack` 与 `chg_bat_unpack`。

```c
/* chg_bms.h */
ChgCtrl ctrl = {.allow = 1, .v_req_01v = 840, .i_req_01a = 400};
uint8_t frame[40];
chg_ctrl_pack(&ctrl, frame, sizeof frame);
ChgBat bat = {.valid = 1, .soc_01pct = 500, .v_pack_01v = 760,
              .v_cell_max_mv = 3900, .v_cell_min_mv = 3800,
              .t_max_c = 35, .t_min_c = 28, .rated_ah_01ah = 200,
              .rated_v_01v = 730, .chemistry = 1, .v_allow_01v = 840,
              .i_allow_01a = 400, .t_allow_c = 55, .remain_min = 30,
              .idx_cell_max = 3, .idx_cell_min = 12,
              .idx_temp_max = 1, .idx_temp_min = 2};
chg_bat_pack(&bat, frame, sizeof frame);

/* chg_charger.h */
ChgCap cap = {.ready = 1, .v_min_01v = 500, .v_max_01v = 1000,
              .i_min_01a = 10, .i_max_01a = 800};
chg_cap_pack(&cap, frame, sizeof frame);
```

充电机以 `chg_apply(&ctrl, &cap, cap_valid, link_ok, paths_conflict, charger_fault, &act)` 计算本周期输出。`cap_valid = 0` 表示该接口不传输能力帧，不要求就绪；调用前仍把书面最大电压和最大电流写入 `cap`。`charger_fault = 1` 表示本机故障或故障码非 0。`cap` 为空时输出 0 A。`chg_apply` 在充电机工程里。

一线通由 BMS 发送充电控制和电池信息。RS-485 由 BMS 先发充电控制，充电机应答能力或状态；电池信息单独发送，充电机不应答。CAN 的充电控制不采用该帧壳；电池信息拆成四帧。

| 方向 | 报文 | ID | 数据 |
|------|------|----|------|
| BMS → 充电机 | BCL | 181056F4 | `48 03 30 11 02` |
| BMS → 充电机 | BRO | 180956F4 | `AA` |
| BMS → 充电机 | BSM 暂停 | 181356F4 | `00 00 00 00 00 00 00` |
| BMS → 充电机 | BST | 181956F4 | `01 00 00 00` |
| 充电机 → BMS | CML | 1808F456 | `E8 03 F4 01 C0 12 AA 0F` |
| 充电机 → BMS | CRO | 180AF456 | `AA` |
| 充电机 → BMS | CCS | 1812F456 | `44 03 2E 11 00 01 01 00` |
| 充电机 → BMS | CST | 181AF456 | `01 00 00 00` |

字节号从 0 起。CAN 电流原始值 = 物理值（0.1 A）+ 4000。40.0 A 对应原始值 4400，字节序为 `30 11`。物理值大于 6153.5 A 时原始值写 65535，不再加 4000 后回绕成小电流。BCL 字节 4 只认 `0x02` 恒流和 `0x01` 恒压。其他值丢掉，不刷新 T_loss，也不改已经保存的电压、电流和恒压位。BRO 与 CRO 只认 `0x00` 和 `0xAA`。其他值丢掉，不改变允许位或就绪位。CML 顺序为最大电压、最小电压、最大电流、最小电流。BSM 字节 6：bit4 = 1 表示未暂停；bit0–bit3 只放绝缘、连接器、单体过压、单体欠压。过温和低温不在这一字节。充电机判定暂停只看 bit4，bit5、bit6、bit7 不参与。bit4 为 0 时，`0x20` 仍是暂停；bit4 为 1 时，`0x30` 不是暂停。flags 为 0 时，未暂停写 `0x10`，暂停写 `0x00`。CCS 8 字节：电压、电流、字节 4 累计时间写 0、字节 5 为 `0x01` 表示正在输出、字节 6 为 `0x01` 表示无故障、字节 7 累计能量写 0。累计时间和累计能量在 BSD，不在 CEM，也不在 CCS。

### 5.10 三个口的字节

三个口的完整时序见图 9、图 10、图 11。图 22 只按 RS-485 画出帧壳发送顺序，回箭不是一线通，也不是 CAN。工况为 50.0–100.0 V、1.0–80.0 A；BMS 在能量传输阶段请求 84.0 V、40.0 A，恒流。


#### 5.10.1 RS-485 字节

BMS 先发，充电机在 80 ms 内应答。握手 = 收到就绪 = 1 的 `0x02`。`0x04` 不应答。上一帧 `0x01` 在 80 ms 内没有合法应答时，下一发送周期重发刚才的 `0x01`，不用 `0x04` 占用该周期。

| 步骤 | 时间 | BMS 发 | 充电机 80 ms 内应答 | 输出电流 | 状态 |
|------|------|--------|---------------------|----------|------|
| 上电 | 调用前 | — | — | 0 A | OFF |
| 握手 | 第 1 次调用 | `A5 5A 01 01 06 00 48 03 00 00 00 7C 5D`（允许 = 0，电流 = 0） | `A5 5A 01 02 09 00 F4 01 E8 03 0A 00 20 03 E7 EC`（就绪 = 0） | 0 A | OFF→HS |
| 电池信息 | 下一发送周期，仍未出流 | `A5 5A 01 04 1C 01 00 F4 01 F8 02 3C 0F D8 0E 23 1C C8 00 DA 02 01 48 03 90 01 37 1E 00 03 0C 01 02 C0 92` | 不应答，不刷新 T_loss | 0 A | HS |
| 握手 | 再下一发送周期 | 与步骤 1 相同的 `7C 5D` | `A5 5A 01 02 09 01 F4 01 E8 03 0A 00 20 03 EA 7C`（就绪 = 1） | 0 A | BMS 进入 RUN；充电机仍为 HS |
| 能量传输 | 再下一发送周期 | `A5 5A 01 01 06 01 48 03 90 01 00 7C 31` | `A5 5A 01 03 06 09 44 03 8E 01 00 8C A7` | 40.0 A | 充电机 HS→RUN |
| 周期 | 能量传输中 | `0x01` 每 250 ms。约每 1 s 单独占用一个发送周期发 `0x04` | `0x01` 应答 `0x03`；`0x04` 不应答 | 跟随最新 0x01 | RUN |
| 暂停 | — | `A5 5A 01 01 06 03 48 03 90 01 00 7D D3`（允许 + 暂停） | `0x03` | 0 A | RUN（不重握手） |
| 恢复 | — | `7C 31`。若该发送周期轮到 `0x04`，先发电池信息，下一发送周期再发本帧 | 收到恢复用的 `0x01` 后应答 `0x03` | 40.0 A | RUN |
| 停止 | — | `A5 5A 01 01 06 04 48 03 00 00 00 7D D9` | `0x03` | 0 A | RUN→STOP |
| 再次握手 | 停止之后 | 从步骤 1 重做。第一个发送周期不应答成就绪 = 1 | 第一个发送周期仍是就绪 = 0 的 `E7 EC` | 0 A | STOP→HS |
| 未应答 | 超过 80 ms | 重发刚才的 `0x01`，不用 `0x04` 占用该发送周期 | 晚到的应答丢弃 | 保持 | 等待中 |
| T_loss | RUN 中到 1.2 s 无合法 `0x01`。不满 1 s 不停 | — | 输出 0 A。同一发送周期开始新的握手，并且不发送 | 0 A | 充电机回到 HS |
| T_loss | RUN 中到 1.2 s 无合法应答。不满 1 s 不停 | BMS 改发停止帧 `7D D9` | — | 0 A | BMS RUN→STOP |
| 下电 | 应用不再调用，或辅助电源撤掉 | 不再发送 | 不再发送 | 0 A | 再次上电从步骤 1 重做，第一个发送周期应答就绪 = 0 |

`0x04` 约每 1 s 单独占用一个发送周期，不与 `0x01` 逐周期交替。插入 `0x04` 时，其两侧的两次 `0x01` 间隔约 500 ms，其余 `0x01` 仍为 250 ms。`0x04` 不刷新 T_loss。上一帧 `0x01` 没收到应答时，只重发 `0x01`。未准备电池数据时，非零电流前的那一帧仍要发送，有效位为 0，CRC 末两字节为 `B7 57`。停止之后只收到能量传输帧 `7C 31`，输出保持 0 A。

#### 5.10.2 一线通字节

SIF 上只有 `0x01` 与 `0x04`。充电机发送脚不接 SIF，不应答。握手 = 连续 3 帧 CRC 正确的 `0x01`；第 1 帧只是 HS 计数，第 3 帧开始出流。能力取书面参数 50.0–100.0 V、1.0–80.0 A。`0x04` 可以和 `0x01` 出现在同一发送周期，不计入连续 3 帧。

| 步骤 | 时间 | BMS → 充电机（SIF） | 充电机 → BMS | 输出电流 | 状态 |
|------|------|---------------------|--------------|----------|------|
| 上电 | 调用前 | 无 | — | 0 A | OFF |
| 握手 1/3 | 第 1 次调用 | `A5 5A 01 01 06 00 48 03 00 00 00 7C 5D`。同一发送周期另发 0x04，不计入 3 帧 | — | 0 A | OFF→HS（sif_sent = 1） |
| 握手 2/3 | +250 ms | `A5 5A 01 01 06 00 48 03 00 00 00 7C 5D`。该发送周期没有 0x04 | — | 0 A | HS（sif_sent = 2） |
| 握手 3/3 + 启动 | +250 ms | `A5 5A 01 01 06 01 48 03 90 01 00 7C 31` | — | 40.0 A | HS→RUN |
| 能量传输 | 之后 | 0x01 每 250 ms。0x04 约每 1 s，可与 0x01 出现在同一次调用 | — | 40.0 A | RUN |
| 暂停 | — | `A5 5A 01 01 06 03 48 03 90 01 00 7D D3`（允许 + 暂停） | — | 0 A | RUN（不重握手） |
| 恢复 | — | `A5 5A 01 01 06 01 48 03 90 01 00 7C 31` | — | 40.0 A | RUN |
| 停止 | — | `A5 5A 01 01 06 04 48 03 00 00 00 7D D9`（停止，电流 = 0） | — | 0 A | RUN→STOP |
| 再次握手 | 停止之后 | 从握手 1/3 重新数，允许 = 0 | — | 0 A | STOP→HS（重新计 sif_sent） |
| T_loss 超时 | 到 1.2 s 无新 0x01。不满 1 s 不停 | BMS 不主动发停止 | — | 0 A | 充电机 RUN→STOP |
| 下电 | 应用不再调用，或辅助电源撤掉 | 不再发送 | — | 0 A | 对端按 T_loss：不满 1 s 不停，到 1.2 s 输出为 0。再次上电从握手 1/3 重新数 |

第一次调用同时发出的 `0x04` 与能量传输期的 `0x04` 都是单独一帧，不替换 `0x01`。未准备电池数据时，这一帧仍发送，有效位为 0。停止期间应用仍在调用时，每 250 ms 继续发送停止帧，电池信息仍约每 1 s 发送。下电后两者都停止。握手、能量传输、暂停、停止的帧尾分别是 `7C 5D`、`7C 31`、`7D D3`、`7D D9`，与 RS-485 同一工况的对应帧相同。步骤号按本表。

#### 5.10.3 CAN 字节

两侧按周期发送。标识符为十六进制。握手阶段 BCL 电流字段为 0，数据 `48 03 A0 0F 02`，会话留在握手。多字节字段为小端；电流原始值 = 物理值 + 4000，40.0 A → `30 11`。

| 步骤 | 时间 | BMS 发 | 充电机发 | 输出电流 | 状态 |
|------|------|--------|----------|----------|------|
| 上电 | 调用前 | — | — | 0 A | OFF |
| 握手 | 第 1 次调用 | BCL `181056F4 / 48 03 A0 0F 02`（电流字段为 0）、BRO `180956F4 / 00`、BSM `181356F4 / 00 00 00 00 00 00 10`。同一发送周期可发四帧 `18EF56F4` | CML `1808F456 / E8 03 F4 01 C0 12 AA 0F`、CRO `180AF456 / 00` | 0 A | OFF→HS |
| 电池信息 | 可与握手处于同一发送周期，之后约每 1 s | 序号 0：`00 01 00 F4 01 F8 02 3C`；序号 1：`01 0F D8 0E 23 1C C8 00`；序号 2：`02 DA 02 01 48 03 90 01`；序号 3：`03 37 1E 00 03 0C 01 02` | 不转发到桩 CAN | 不变 | 不计入就绪 |
| 就绪 | 见到 BRO = 00 之后 | 见到 CRO = AA 后，下一发送周期 BRO 改为 `AA`，BCL 改为真实请求 | CRO `180AF456 / AA` | 0 A | HS |
| 能量传输 | BCL 50 ms | BCL `181056F4 / 48 03 30 11 02`、BRO `AA`、BSM `181356F4 / 00 00 00 00 00 00 10` | CCS `1812F456 / 44 03 2E 11 00 01 01 00` | 40.0 A | HS→RUN |
| 暂停 | — | BCL 不变；BSM `181356F4 / 00 00 00 00 00 00 00`（字节 6 = `0x00`） | CCS 可继续 | 0 A | RUN（不重握手） |
| 恢复 | — | BSM 字节 6 = 0x10 | CCS 继续 | 第一拍 ≤20.0 A，下一拍 40.0 A | RUN |
| 仅 BCL 电流为 0 | 未发 BST | BCL `181056F4 / 48 03 A0 0F 02` | 输出回到 0，不按最小电流续出，会话保持 | 0 A | RUN |
| BST 停止 | — | BST `181956F4 / 01 00 00 00`，10 ms 内发出 | 本机故障时另发 CST `181AF456 / 01 00 00 00` | 0 A | RUN→STOP |
| 再次握手 | 停止之后 | BCL 电流字段为 0，BRO = 00 | CML，CRO 回到 00。只收到 BCL 与 BRO = AA 不能恢复输出 | 0 A | STOP→HS |
| T_loss 超时 | 到 1.2 s 无 CCS。不满 1 s 不停 | BMS 发 BST，并保持停止，直到请求电流先回到 0。停留在停止期间按 10 ms 重发 BST，不再发 BCL | 到 1.2 s 无 BCL 时，充电机输出 0 A，CRO 回到 00，该发送周期不另发能量帧 | 0 A | RUN→STOP |
| 下电 | 应用不再调用，或辅助电源撤掉 | 不再发送 | 不再发送 | 0 A | 再次上电从握手重做，CRO 从 00 开始 |

`0x18EF56F4` 是 PDU1 厂商私有高位区（PF=`0xEF`，PGN `0xEF00` / 61184），只在 BMS 与充电机之间的 CAN 上出现。充电机收齐四帧按 28 字节组装 `0x04`，并把字段搬到桩 CAN 上的 BRM/BCP/BCS/BSD。桩 CAN 上的 BSD 标识符是 `0x181C56F4`，与本四帧不同。

#### 5.10.4 异常时的帧

判据在第 4 节。下表只把同一条判据写成三个口能对上的帧。帧壳丢弃由 `frame_unpack` 处理。

| 异常 | 一线通 | RS-485 | CAN | 输出电流 |
|------|--------|--------|-----|----------|
| CRC、VER、报文号错误 | 丢弃，不计入 3 帧 | 丢弃，不算应答 | 短 DLC 或不能识别的标识符整帧忽略 | 不变 |
| 字节间隔 > 50 ms | 半帧丢弃 | 半帧丢弃，BMS 继续等待或在 80 ms 后重发 `0x01` | 不适用 | 不变 |
| 第一个发送周期没有及时应答 | 无应答概念 | 超过 80 ms 则重发 `7C 5D`，不发送 `C0 92` | 两侧按周期重发，不靠应答推进 | 0 A |
| 能量传输中到 1.2 s 仍无合法输出目标帧。不满 1 s 不停 | 充电机进入 STOP。BMS 不主动发停止 | 充电机回到 HS 且该拍不发送。BMS 发 `7D D9` | 充电机回到 HS，CRO 回到 00。BMS 发 BST | 0 A |
| 只有 BCL 电流字段为 0 | 不适用 | 请求电流为 0 且已经在 RUN，按停止 | `48 03 A0 0F 02` 且没有 BST：输出 0 A，会话保持 | 0 A |
| 充电机本机故障 | 输出 0 A | 输出 0 A。状态帧可带故障 | 发送 CST `01 00 00 00` | 0 A。下一次非零请求从允许 = 0 重新握手（CAN/RS-485 立即 begin_handshake(HS)，一线通从 OFF/HS 重新走） |
| 电池信息无效 | 有效位 0 的 `0x04` 仍发送，末两字节 `B7 57`。不计入 3 帧 | 非零电流前的那一发送周期仍发送有效位 0。不应答 | 四帧未收齐则不更新。收齐但有效位为 0 时，桩侧不进入能量传输 | 家充仍按 `0x01` |
| 停止后直接给能量传输帧 | 未重新数满 3 帧则输出 0 A | 直接收到 `7C 31`，输出保持 0 A | 只收到 BCL 与 BRO = AA，输出保持 0 A | 0 A |
| 下电 | 不再调用后，停止帧和 `0x04` 都停止 | 不再调用后，总线上没有新的主站帧 | 不再调用后，BST 与四帧都停止 | 0 A。再次上电不保留就绪位 |

下电没有单独的报文。辅助电源撤掉或应用停止调用之后，对端若仍在能量传输，按上表「到 1.2 s 没有合法 `0x01` / BCL」处理。充电 MOS 在会话进入 STOP 后 1 s 内断开，这 1 s 与 T_loss 分开计。直流输出在 `enable = 0` 时断开。

每条都有现成的 C 测试用例可以核对（`test_chg_bms.c`、`test_chg_charger.c` 内 `test_edges` 与 `test_session_state`）。

- 一线通 CRC 错：`test_chg_charger.c::test_edges::sif bad crc skips`；BMS 侧：`test_chg_bms.c::test_edges::bad crc waits / bad crc not ready`。
- RS-485 CRC 错：`test_chg_bms.c::test_edges::good reply`（在收到坏帧后等下一帧）。
- 时间间隙 > 50 ms：BMS 侧 `test_chg_bms.c::test_485::gap drops`，充电机侧 `test_chg_charger.c::test_485::485 gap`。
- 未知 MSG：BMS 侧 `test_chg_bms.c::test_bat::485 ignores query`。
- DLC 不足：充电机侧 `test_chg_charger.c::test_edges::short bcl ignored`。
- 端到端会话回归：充电机侧 `test_chg_charger.c::test_session_state`，一次性跑完三个口的握手、能量传输、暂停→恢复、停止→重新握手与 BST。
- T_loss 超时：BMS 侧 `test_chg_bms.c::test_485::loss stops` / `test_can::loss stops`，充电机侧 `test_chg_charger.c::test_sif::sif loss` / `test_can::can loss` / `test_485::485 loss`。

## 6. 一线通

报文含义见第 5 节，发送顺序见第 3 节。本节只写这个口的传输差异。物理层符合第 2 节。

- BMS 以 T_ctrl（250 ms）为周期发送一帧，MSG = `0x01`，DATA 为第 5.3 节的 6 字节。
- BMS 以 T_bat（1000 ms）另发 `0x04`。第一次调用会与第一帧 `0x01` 处于同一发送周期发出。该帧不计入连续 3 帧握手，也不改变输出电流。
- `0x02` 与 `0x03` 不在本接口传输。充电机发送脚不接 SIF。最小输出电压、最大输出电压与最大持续电流以书面参数给出。
- 握手条件为连续 3 帧 CRC 正确的 `0x01`。出流条件仍按第 5.7 节执行。
- 充电机识别 `0x01` 做充电控制，识别 `0x04` 做电池信息。SIF 上的其他帧不参与出流判断。**一线通协议的老式仪表若不识别 `0x04`**：可以仍按其原 BMS 查询帧格式使用 SIF（只听不参与握手、出流）；但仪表不应伪装 BMS（即不能误发 `0x01`，那会被本规范的充电机当作充电请求而跟随）。
- 线上实例为第 5 节的充电控制帧。充电机不回传。能力与状态采用第 5 节同一组数值，以书面参数提供。

### 6.1 状态 ↔ SIF 行为表

| 充电机状态 | SIF TX（BMS 端） | SIF TX（充电机端） | SIF 上拉 | 备注 |
|------------|------------------|-------------------|----------|------|
| OFF | 不发（含上电未完成、本机故障未恢复） | 高阻（不接 SIF） | 关闭（上拉交回仪表） | 仪表可独占 SIF；故障恢复后仍从 OFF 重新走 |
| HS | 周期 0x01（250 ms）+ 0x04（1 s） | 不接 | **打开上拉 5 V / 2.2 千欧** | 上拉只在 HS 及之后打开 |
| RUN | 周期 0x01（250 ms）+ 0x04（1 s） | 不接 | **打开上拉 5 V / 2.2 千欧** | — |
| STOP | 应用仍调用时，每 250 ms 发停止帧；下电后不再发。`0x04` 在下电前仍约每 1 s 发送 | 不接 | 关闭（交回仪表） | 见第 3 节状态 6、状态 7 |

充电机的 **TX 脚永远不接 SIF**（见 `chg_charger/src/chg_charger.c` 中 SIF
路径不使用 `HAL_GPIO_WritePin` 推挽输出，及第 2 节表「充电机发送脚不接 SIF」）。
充电机发送脚不得接到 SIF，接到 SIF 会损坏 BMS 的开漏输出。

### 6.2 字节间隔 ≤ 50 ms 半帧判定

- BMS 发一帧前，确认 SIF 已空闲 ≥ 1 ms（避免上电残留）。
- 字节间最小间隔 0（UART 一帧连续发送）。
- 字节间最大间隔 50 ms：超出视为上一帧丢半，BMS 重找下一 `A5 5A`。
- 帧末（CRC 高字节发出后）到下一帧起始 ≥ 1 ms。
- 充电机收 `gap_ms > T_GAP_MS (50)` 清 `raw_n = 0`，回到帧头搜索
  （`chg_charger/src/chg_charger.c:528-547`）。
- BMS 同样按此判定：>`T_GAP_MS` 丢弃半帧，重新搜帧头
  （`chg_bms/src/chg_bms.c:702-727`，`bms_link_rx_byte`）。

### 6.3 仪表并行听

仪表与充电机共线时的脉宽帧不在本文。下面四条只用于不接仪表的一线通。

- 仪表是只听节点，但有上拉接入能力时，仪表须让出上拉给充电机：充电机进入
  ARM 后打开上拉，仪表必须放弃上拉；反之亦然。
- 充电机阶段为 OFF 时，SIF 上的字节整段丢掉，握手计数保持 0，输出保持 0。第一次 `chr_link_tick` 进入 HS，此后的 `0x01` 才计入连续 3 帧。
- 仪表可以读取 BMS 的 0x04 用于显示（荷电、温度），但不能改 BMS 的发送节奏或写充电机的能力。
- HS 和 RUN 期间，软件把任何合法 `0x01` 都计入握手。这两段时间上拉由充电机打开，仪表不得发 `0x01`。上拉脚的电平在硬件在环步骤 10 核对。软件在环用阶段 OFF 代表上拉尚未打开。

### 6.5 上拉电阻尺寸与供电

- 5 V 系统：上拉电阻 = **2.2 千欧 ± 5%**（分压后高电平 ≥ 3.5 V，低电平 ≤ 0.4 V）。
- 3.3 V 系统：上拉电阻 = **1 千欧 ± 5%**。
- 上拉 VCC 取 5 V（即使 MCU 是 3.3 V）；通过分压给 MCU 采样。
- 上拉由充电机控制（HS 打开，OFF/STOP/FAULT 关闭）；BMS 不带内部上拉。

### 6.6 SIF 错误与安全

| 现象 | 充电机动作 |
|------|------------|
| SIF 持续拉低 ≥ 100 ms（外部短路） | 进入 FAULT；`act.enable=0`；不再打开上拉 |
| SIF 上意外的长 ≥ 5 s 间隔 | 视为通信断开；按 T_loss 处理；关闭上拉 |
| 充电机自检发现 SIF 线对地短路 | FAULT；硬件修复前不开上拉 |

调用方每个周期把当前电平送进 `chr_link_set_sif_state`（BMS 侧为 `bms_link_set_sif_state`）。`b=1` 是空闲高电平，`b=0` 是拉低。累计满 100 ms 进入物理断开；未满 100 ms 的毛刺清零后不影响出流。CRC 错误不重置这只计数器。

## 7. RS-485

报文含义见第 5 节，发送顺序见第 3 节。一条总线一只 BMS。半双工的问答应答见图 23。帧内没有站地址，帧以 `A5 5A` 开头。CRC 算法与 Modbus CRC-16 相同，帧不是 Modbus RTU。


```c
bms_link_init(&blink, CHG_PORT_485);
bms_link_tick(&blink, &ctrl, 0, &btx);                 /* BMS 先发 0x01 */
chr_link_rx_byte(&clink, byte, gap_ms, &meas, &tx);    /* 充电机应答 */
bms_link_rx_byte(&blink, byte, gap_ms, &ctrl, &btx);   /* 收下应答 */
```

用第 5 节的同一组数，能量传输的一问一答是：

BMS 发送充电控制：

```
A5 5A 01 01 06 01 48 03 90 01 00 7C 31
```

充电机应答状态：

```
A5 5A 01 03 06 09 44 03 8E 01 00 8C A7
```

握手时充电机改应答能力。第一次就绪 = 0，见到允许 = 0 的请求后再应答就绪 = 1：

```
A5 5A 01 02 09 00 F4 01 E8 03 0A 00 20 03 E7 EC
A5 5A 01 02 09 01 F4 01 E8 03 0A 00 20 03 EA 7C
```

电池信息由 BMS 另发一帧，充电机不应答。字节见第 5 节。

厂家已有其他帧格式时，按第 5 节的字段一一映射，并交出版本、CRC 和字节序。映射之后，停止和请求电流 0 仍是输出 0 A。BMS 仍是请求方。

RS-485 对地或对电源短路持续 ≥ 100 ms，按物理断开处理，不等 T_loss。BMS 调用 `bms_link_set_485_short`，充电机调用 `chr_link_set_485_short`。`shorted=1` 为短路。硬件比较器由厂商接这只函数；链路层负责 100 ms 计数和停流。线没恢复之前，总线上的字节一律丢掉。

## 8. CAN

报文含义见第 5 节，发送顺序见第 3 节。不采用第 5 节的帧壳。两根线的周期和地址见图 24。这条 CAN 上，BCL、BRO、BST 的标识符与 A 类相同，BCL 为 5 字节。BSM 和 CCS 是第 5 节的短装，不是第 11.3.3 条、第 11.3.4 条。桩侧产品另按第 11 章组帧。


源地址：BMS 为 **0xF4**，充电机为 **0x56**。多字节字段为小端。通用报文中的电流为正值；映射至 CAN 时，**充电电流的原始值 = 物理值(0.1 A/bit) + 4000**（即 −400 A 偏移），与 `chg_can_bcl` / `bms_link_can_rx` 的 `can_i_raw` / `can_i_phys` 一致（见 `chg_charger/src/chg_charger.c` 与 `chg_bms/src/chg_bms.c`）。40.0 A 对应原始值 4400 = `0x1130`，小端为 `30 11`。大于 6153.5 A 时写 65535。收到的原始值小于 4000 时按 0 A，不解释成负电流。

控制器报 bus-off 持续 ≥ 100 ms，按物理断开处理，不等 T_loss。BMS 调用 `bms_link_set_bus_off`，充电机调用 `chr_link_set_bus_off`。`bus_off=1` 为故障。这 100 ms 与 CRC 错、DLC 不够不是同一只计数器：bus-off 期间到来的帧直接丢掉，不能靠一帧碰巧解出来的 CCS 或 BCL 把输出拉回去。

| 通用字段 | CAN 报文 | 周期 |
|----------|----------|------|
| 请求电压、请求电流、恒压 | BCL | 50 ms |
| 允许 | BRO：允许且握手完成 = `0xAA`，否则 `0x00` | 250 ms |
| 暂停 | BSM「禁止充电」 | 250 ms |
| 停止 | BST | 进入停止的当周期发出，停留期间每 10 ms 重发 |
| 充电机能力 | CML | 握手及能力变化 |
| 就绪 | CRO：就绪 = `0xAA` | 250 ms |
| 输出电压、输出电流 | CCS | 50 ms |
| 故障 | CST 或 CEM | 事件 |
| 电池信息 | `0x18EF56F4`，四帧 | 1000 ms |

`0x18EF56F4` 的优先级为 6，PF 为 `0xEF`，目标地址 `0x56`，源地址 `0xF4`。这是 **PDU1 厂商私有高位区（PGN 61184, `0xEF00`）**：PF=0xEF（239）属 PDU1（PF≤239 仍为 PDU1，PS=目标地址），J1939-71 把 0xEF00 列为厂商可声明的 PGN；本规范把目标填 `0x56`（充电机）、源地址 `0xF4`（BMS），不与 GB/T 27930 的任何 PGN 冲突。桩侧 BSD 的标识符是 `0x181C56F4`（PF=0x1C PDU1，BSM 与 BSD 不在同一链路）。电池信息留在 BMS 与充电机之间的 CAN 上，由充电机翻译后再按国标报文发给桩。

四帧按序号 0、1、2、3 发送。每帧 8 字节：字节 0 为序号，后 7 字节为第 5 节的 28 字节载荷。序号 0 开始新的一组。收齐四帧后按 28 字节解析。BMS 周期推送，第一次调用即可与握手 BCL 处于同一发送周期发出，不改变电流，也不计入就绪。充电机不向 BMS 索取电池信息。

面向国标直流桩时，充电机在自己的桩 CAN 上按 GB/T 27930 组 BRM、BCP、BCS、BSD，字段来自最近一帧有效 `0x04`。桩 CAN 与这条 BMS CAN 不共线。

请求电流为 0、暂停与停止都使输出为 0 A。CAN 上要分开看。

| 通用语义 | CAN 上的帧 | 节奏 |
|----------|------------|------|
| 能量传输中请求电流变为 0 | BMS 进入停止并发 BST，不再发 BCL | 停留期间每 10 ms |
| 只收到 BCL 电流为 0，没有 BST | 输出 0 A，会话保持，不按最小电流续出 | — |
| 暂停 | BSM 字节 6 的 bit4 为 0。flags 为 0 时整字节是 `0x00`，未暂停是 `0x10`。bit5 不参与 | 每 250 ms |
| 停止 | BST `01 00 00 00` | 进入停止当周期即发送，之后每 10 ms |

只收到 BCL 时，充电机用 `from_can_bcl_only` 保持会话。BMS 在应用请求电流为 0 时自己进入停止。到 1.2 s 没有 CCS，BMS 发 BST，并保持停止，直到请求电流先回到 0。不满 1 s 不发。B 类、超充和 V2G 不在本链路实现。

下表为第 5 节同一组工况的 CAN 帧。电流原始值 = 物理值（0.1 A）+ 4000。40.0 A 的原始值为 4400，字节序为 `30 11`。

| 方向 | 报文 | ID | 数据 |
|------|------|----|------|
| BMS → 充电机 | BCL | `181056F4` | `48 03 30 11 02` |
| BMS → 充电机 | BRO | `180956F4` | `AA` |
| BMS → 充电机 | BSM，未暂停 | `181356F4` | `00 00 00 00 00 00 10` |
| BMS → 充电机 | BSM，暂停 | `181356F4` | `00 00 00 00 00 00 00` |
| BMS → 充电机 | BST | `181956F4` | `01 00 00 00` |
| 充电机 → BMS | CML | `1808F456` | `E8 03 F4 01 C0 12 AA 0F` |
| 充电机 → BMS | CRO | `180AF456` | `AA` |
| 充电机 → BMS | CCS | `1812F456` | `44 03 2E 11 00 01 01 00` |
| 充电机 → BMS | CST | `181AF456` | `01 00 00 00` |
| BMS → 充电机 | 电池信息，序号 0–3 | `18EF56F4` | `00 01 00 F4 01 F8 02 3C`，然后 `01 0F D8 0E 23 1C C8 00`，`02 DA 02 01 48 03 90 01`，`03 37 1E 00 03 0C 01 02` |

BCL 前两字节是 84.0 V，接着两字节是 40.0 A，末字节 `02` 表示恒流。CML 顺序是最大电压、最小电压、最大电流、最小电流。CCS 前四字节是 83.6 V 和 39.8 A。BSM 字节 6：暂停为 `0x00`，未暂停为 `0x10`（flags 为 0）。充电机只看 bit4：`0x20` 仍暂停，`0x30` 不暂停。

```c
ChgCan bcl, ccs, bst, bat_can[4];
chg_can_bcl(&ctrl, &bcl);             /* BMS 发送 */
chg_can_bat(&bat, bat_can);           /* 四帧，标识符 18EF56F4 */
chg_can_bst(&bst);                    /* 停止用 BST，不用 BCL */
chg_can_ccs(&meas, &ccs);             /* 充电机发送 */
bms_link_can_rx(&blink, &ccs);
chr_link_can_rx(&clink, &bcl, &meas, &tx);
```

#### 9.3.1 门禁与覆盖率

`chg_evcc/Makefile` 的 `ci` 目标即 CI 门禁，依次执行：

1. `make test`：跑 `tests/test_chg_evcc.c` 的全部单测。

   `CI FAIL: <scn> drifted` 并附 `build/ci/<scn>.diff` 前 50 行。
4. `tools/check_traceability.sh`：校验 § ↔ 用例追溯矩阵里引用的每个文件都存在。

`sim_replay` 读已写出的 `events.jsonl`，只检查 `t_ms` 是否单调。它不重跑场景，也不比对报文。报文比对是 `sim_assert_golden`：同一组输入再跑一遍 `sim_step_bms_to_evcc`，把新的 `golden.csv` 与 `tests/golden/` 里的文件对齐。`events.jsonl` 由 `sim_record` 写入。

### 9.5 软件在环(SIL)与硬件在环(HIL)的分层

软件在环(SIL)是 Software-in-the-Loop，硬件在环(HIL)是 Hardware-in-the-Loop。这是 GB/T 34590 的用语，括号里是英文缩写，不是另起的译名。

左侧是分解，右侧是逐级验证。软件在环(SIL)是主机上一个进程里的背靠背。硬件在环(HIL)要目标板和可注入的物理故障。本仓做到软件在环(SIL)。硬件在环(HIL)的十步在 9.6，尚未执行。

| V 模型左侧 | 本仓 |
|------------|------|
| 系统需求 | 第 10 节验收 1–17，第 4 节异常表，第 10.1 节 ASIL 分配 |
| 系统架构 | 第 1–3 节：三个口一次只用一个，会话 OFF/HS/RUN/STOP |
| 软件详细设计 | 第 5–8 节报文，第 12 节桩侧映射 |
| 实现 | `chg_bms`、`chg_charger`、`chg_evcc` |

| V 模型右侧 | 本仓对应 | 验证什么 | 没有覆盖 |
|------------|----------|----------|----------|
| 软件单元 | `test_chg_bms`、`test_chg_charger`、`test_chg_evcc` | 单侧组帧、状态机、100 ms 计数、字节 | 看不到对端 |
| 软件在环(SIL) | `e2e/harness.c` 把 BMS 与充电机链在一个进程里；`chg_battery_sim` 是被控对象模型，不是台架。`chg_evcc` 场景是桩侧软件在环，golden 比对 | 三口握手 / 暂停 / 恢复 / 停止 / 重握；cap 钳位；T_loss 时充电机输出已经是 0（CAN/485 的 BMS 也 STOP）；验收 15 两侧同时锁存且帧不能把电流拉回去；验收 14 故障帧在 800 ms 内让 CAN/485 的 BMS 停（短于 T_loss）；三口不调用 `set_bat` 仍出流且读不出电池信息；三口欠压标志 50 ms 仍出流、100 ms 为 0；OFF 阶段丢掉合法 `0x01`；长 RUN 的 SOC 上升、温度不降、输出电压不超过请求 | 不在目标 MCU 上。线故障和欠压是软件标志。没有线延迟，没有时钟偏差，看不到上拉脚电平 |
| 处理器在环(PIL) | 无 | — | 没有 STM32 / S32K 工程 |
| 硬件在环(HIL) | 无 | — | 需要目标板、可注入的物理故障（SIF 拉低、CAN 控制器 bus-off、485 短路）和电池模拟器或电子负载。主机里的 OCV 模型不是 HIL |
| **Vehicle** 装车 | 无 | — | 整车 BMS、VCU、桩，归 OEM |

软件在环电池模型的换算如下。除法都先加半个分母再除。桩侧短装的字节上限仍按第 12 节，不在这张表里重复。

| 量 | 算法 | 锁定例子 |
|----|------|----------|
| 时间 | 毫秒累计，满 1000 ms 才算 1 s | 50 ms 的一拍不计 1 s |
| 电池包电压 | `(cell_mv × 串联节数 + 50) / 100`，大于 65535 写 65535 | 3653 mV × 20 → 73.1 V。3650 mV × 20 → 73.0 V |
| 剩余时间 | `(6 × 容量 × 剩余荷电 + 500) / 1000`，再封顶 65535 min | 20.0 Ah、99.97% → 4 min。半满仍是 6000 min。65538 min → 65535。桩侧大于 254 min 写 254 |
| 单体电压 | 开路电压 ±5 mV，限制在 0…65535 | 0 mV 的最低电压写 0 |
| 荷电 | `(i_01a × 秒 + 18) / 36`，再按容量四舍五入到 0.01% | 1.8 A、20.0 Ah、1 s：50.00% → 50.05%。15.0 Ah 同一拍加 0.07 个百分点。40.0 A、20.0 Ah、1 s 加 0.55 个百分点 |
| 阻容目标 | `(i_01a × mΩ + 50) / 100` | 40.5 A、15 mΩ → 61 mV。40.0 A、15 mΩ → 60 mV |
| 阻容步进 | 向目标靠拢，先加半个分母 | 1.7 A、15 mΩ、时间常数 5 s、1 s → 1 mV。40.0 A、1 s → 10 mV |
| 开路电压 | 等距分段用 `10000 / 段数`，段内先加半段 | 默认七点表 99.99% → 4200 mV，50.00% → 3700 mV。两点 3000 mV 与 3400 mV，0.13% → 3001 mV，50.00% → 3200 mV |
| 温度 | 0.1 A 直接平方。功率、热容、摄氏度都先加半个单位。每 1 s 向环境挪 1°C | 40.0 A、30 mΩ、热容 96、25°C、1 s → 74°C。40.2 A → 75°C。40.5 A → 75°C。10.8 A、热容 20 → 42°C。0.7 A、热容 1 → 26°C。40°C、电流 0、2 s → 38°C |

`make -C firmware/e2e test` 是软件在环门槛。`make -C firmware/chg_evcc ci` 是桩侧软件在环加 golden 门槛。两边都过，仍然没有硬件在环(HIL)。

### 9.6 软件在环(SIL)与硬件在环(HIL)的测法

本节是本仓库核对参考代码的方法。联调验收以第 10 节为准。充电机厂家收到 `chg_charger`，按第 5.10 节组帧。第 1、3、4 步用到的 `chg_bms`、`e2e`、`chg_evcc` 不发给充电机。软件在环的通过记录不能填进硬件在环表，也不代替第 10 节，更不代替 GB/T 34658。

**软件在环(SIL)。** 目的：在一台主机的一个进程里核对第 3 节、第 4 节和第 5 节。条件：仓库根目录，C11 编译器；不接目标板，不接桩；不测量导线上的时间；辅助电源和线故障是软件标志。在仓库根目录依次执行。前一步未通过时，不把后续步骤记为通过。

| 步骤 | 命令 | 应看到 | 本步核对 |
|------|------|--------|----------|
| 1 | `make -C firmware/chg_bms test` | `ok` | BMS 组帧、状态机、100 ms 线故障和辅助电源 |
| 2 | `make -C firmware/chg_charger test` | `ok` | 累计到 1000 ms 不触发超时，到 1200 ms 触发。暂停恢复第一拍不超过 20.0 A，电压目标减 1.0 V |
| 3 | `make -C firmware/e2e test` | 每个口一行 `ok`，最后一行 `ok` | 做法见 `e2e/README.md`。下表 a 至 h。静默 900 ms 和 1000 ms 仍出流，1200 ms 为 0 |
| 4 | `make -C firmware/chg_evcc ci` | `traceability: ok`，且没有 `CI FAIL` | 桩侧单元测试、场景和 golden。RTS 在 CTS 之前。DT 间隔 10 ms。周期 ±10% 不结束会话 |

第 3 步按 `e2e/harness.c` 的顺序执行：

| 顺序 | 做法 | 应断言 |
|------|------|--------|
| a 三口会话 | 一线通、CAN、RS-485 各一遍。能力上限 30.0 A，请求 40.0 A | 输出 30.0 A。暂停时 0 A 且会话保持。恢复后第一拍电流不超过 20.0 A，电压目标为请求减 1.0 V。停止后为 0。再次非零请求应重新握手 |
| b 三口静默 | 进入能量传输后停止把帧交给对端。时间从最后一帧算起 | 900 ms 和 1000 ms 处输出仍在，会话仍在能量传输。1200 ms 处输出为 0。CAN 与 RS-485 的 BMS 进入停止。一线通的停流在充电机 |
| c 三口线故障 | 线故障标志先置 50 ms，再置 50 ms | 50 ms 时仍有电流。满 100 ms 两侧锁存且电流为 0。锁存期间继续送帧，电流仍为 0。线恢复且请求电流先回到 0 之后可以再出流 |
| d 三口充电机故障 | `meas.fault` 置 1，观察不超过 800 ms | 三口输出为 0。CAN 与 RS-485 的 BMS 进入停止。一线通只核对输出为 0 |
| e 无电池信息 | 三个口都不调用 `bms_link_set_bat`，走到能量传输 | 输出电流非 0。`chr_link_bat` 返回失败 |
| f 辅助电源 | 三个口把欠压标志先置 50 ms，再置 50 ms | 50 ms 时仍有电流。满 100 ms 输出为 0，BMS 进入停止 |
| g 仪表 | 一线通在第一次 tick 之前连续送 3 帧合法 `0x01`。能量传输中再写入 8 个非帧字节 | 第一次 tick 之前输出为 0，握手计数为 0。第一次 tick 进入握手，计数仍为 0。非帧字节不改变已有输出 |
| h 电池模型 | 三口各做一次长运行 | 荷电状态上升，温度不下降，输出电压不超过请求 |

合格判据：四步退出码都为 0，第 3 步最后一行是 `ok`，第 4 步有 `traceability: ok` 且没有 `CI FAIL`。记录日期、提交号、四个退出码和第 3、第 4 步标准输出的末行。

代码示例里，CAN 的一个控制周期应把 `btx.can_n` 的每一帧交给 `chr_link_can_rx`，再 `chr_link_tick`，然后把 `ctx.can_n` 的每一帧交给 `bms_link_can_rx`。功率给定读 `ctx.act`。从初始化走出的那一拍仍在握手。能量传输稳态下，84.0 V / 40.0 A 且能力上限不低于 40.0 A 时，`i_out_01a` 应为 400。暂停撤销后第一次出流不超过 200，电压目标为 830。

**硬件在环(HIL)。**

方法：被测件是运行本通信栈的 BMS 板和充电机，负载用电池包或电子负载。一次只接一个口，接线按第 2 节。电流探头串在直流输出上，电压表接在辅助电源上，报文工具和记录仪共用一个时间零点。线故障和欠压由夹具注入，不在软件里置标志。开始前，板上软件与软件在环记录的提交号相同，输出电流为 0。下一步开始前，上一步的预期结果已经出现。


图注：左为注入，右为和报文对齐的测量。停发看 900 ms 和 1200 ms。拉低、bus-off、短路和欠压看 50 ms 和 100 ms。

| 步骤 | 方法 | 预期结果 |
|------|------|----------|

### 11.4 BMS 充电 MOS 与握手

| BMS 链路状态 | MOS 状态 |
|--------------|----------|
| OFF / HS / 链接物理断开 | 关 |
| RUN（HS 满足条件后 BMS 自行判断） | 可以开；BMS 决定何时闭合 |
| STOP | 关，1 s 内完成 |

BMS 的 MOS 闭合决策不在本规范范围内，由 BMS 充电策略决定（见
`bms_strategy/`）。本规范仅规定：当 BMS 链路从 RUN → STOP 时，
BMS 必须在 1 s 内把 MOS 关回。

### 11.5 `bms_link_set_bat` 时机

- BMS 在 `bms_link_init` 之后、上电自检完成时调用 `bms_link_set_bat(&bat)`。
- 之前或传入 NULL：帧仍发送，有效位为 0。桩侧不进入能量传输。BRM、BCP、BSM、BCS 的电池字段写 0。BSD 的未知项按第 12 节写 0xFF。
- 期间 0x01 仍可发，握手、出流不受影响（`chg_apply` 不读 0x04 任何字段）。

### 11.6 一线通 → CAN ↔ RS-485 切换（订单特例；主线仍是三选一）

订单可以同时支持两种口（同一次充电只有一个口）。切换时必须先 STOP 当前会
话，禁上拉，再打开新口的上拉 / 终端电阻，1 s 内允许新口握手。否则会被两
个口的计时器并行累计 T_loss，导致误 STOP。

注：本节为订单特例，**主线仍是 §2 的三选一**（一线通 / CAN / RS-485
中只装一个）；只有当一台机器实际支持两种口并存时，才按本节做切换。

---
